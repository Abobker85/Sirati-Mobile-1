# Sirati Flutter app: memory for coding agents

- Stack: Flutter 3.44, Dart 3.12, Riverpod 3 (`AsyncNotifierProvider.autoDispose`, sealed outcome classes). Arabic RTL is the default locale; English supported.
- Layout: `lib/core` (network, storage, routing, utils) -> `lib/shared` (models, services, theme, widgets) -> `lib/features/*`. Features: app, ats_scanner, auth, cv_builder, cv_export, dashboard, jobs, localization, settings.
- Colours: use `context.sirati` tokens. `primary` is a fill (white `onPrimary` text on it); use `primaryInk` for teal text. Raw `Color(0x…)` is blocked by `test/app_metrics_test.dart`.
- Contrast is tested: `test/support/contrast_probe.dart` (`expectAllTextAa`). Text >= 4.5:1, graphics >= 3:1.
- Direction icons: use `DirectionalIcon` (mirrors once in RTL).
- `lib/l10n/generated` is gitignored and generated; never commit it.
- Tests: `flutter test <path>`; goldens in `test/golden` (`--update-goldens` only when a visual change is intended).
- Backend API base: `lib/core/network/api_config.dart` (`https://siratie.com/api`).
- Feature docs live in `docs/features/*.md` (index: README.md); update the matching file when behaviour changes.
- Analysis history lives in `lib/features/dashboard` (`analysesHistoryProvider`, `GET /cv-analyses`), not in ats_scanner.
- Only HTTP 401 logs out; 403 is typed `auth` but never logs out. `AnalyticsService` is a debug-print no-op; `app_open` still goes to `POST /mobile/activity`.
- Sign-out teardown is `LocalSessionCleanup` (lib/shared/services/local_session_cleanup.dart): every step runs, failures are aggregated; remote logout always runs. Content caches use a generation counter + rotating disk epoch so late writes never reach the next account.
- `settings_screen.dart` and other l10n-adopted screens must take copy from the ARB files (`test/localization/l10n_adoption_test.dart`).
- Purchases: RevenueCat behind `StorePurchases` (lib/shared/services/purchases). Key only via `--dart-define=REVENUECAT_IOS_KEY` (Codemagic env); RevenueCat app user id must equal the backend user id (the webhook resolves the account by it). Access is granted only by the server (`/auth/me`), never by the store result. Tests override `storePurchasesProvider`; the default is unavailable in tests (not iOS, no key). The adapter runs SDK calls one at a time behind `RevenueCatClient` (fakeable) and refuses a purchase for an account other than the one offers were loaded for; the gate re-reads `/auth/me` before buy/restore and binds the whole flow to that account (`isCurrent` checked again inside the queue right before the store call; polling counts only that account's `/auth/me`; a session change resets the flow). The plain "refresh" also drops a reply once the session moved to another account or signed out (`_refreshStillCurrent`; an unknown session at start is not a change). Widget tests that assert something is absent from the gate's lazy ListView must jump to the top and use `skipOffstage: false`. `AuthApiService.me()` writes `SessionCache` only if no other session write happened during the request. After a purchase or restore the app calls `POST /subscriptions/restore`, which makes the backend re-read the subscriber from RevenueCat (needs `REVENUECAT_API_KEY`, the secret sk_ key; 503 without it outside local). Trials show only when RevenueCat confirms intro eligibility, in the store's own unit. Transfer policy: a subscription stays with the buying account (RevenueCat restore behaviour "Keep with original App User ID"); the app shows premiumGateOtherAccount and the backend logs TRANSFER as critical and reconciles every involved account with RevenueCat (503 and not recorded if RevenueCat is down, so it is redelivered). Codemagic: `ios-testflight` requires a committed `ios/Podfile.lock` and an `appl_` REVENUECAT_IOS_KEY; run the `ios-pod-lock` workflow to produce the lock.
- Widget tests in Arabic may need a taller view (`tester.view.physicalSize`) or taps land off-screen.
- Premium status for UI: `AuthUser.subscriptionStatus` (lib/shared/models/subscription_status.dart; only `is_subscribed: true` counts). `ProfilePhoto(premium: ...)` draws the gold badge; Settings has a Subscription section (`SettingsScreen.subscriptionKey`, iOS-only Manage link to Apple).
- Premium UI: mark Premium features with `PremiumChip` and open `PremiumPromptSheet.show(context, PremiumFeature.x)` (lib/shared/premium); never disable a locked feature. 402s through `AppSnackBar.fromException` already open the prompt. See docs/features/dashboard.md.
